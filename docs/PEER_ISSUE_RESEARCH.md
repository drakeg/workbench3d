# Peer issue research and independent implementation plan

Reviewed November 21, 2026. This is a list of user needs inspired by other projects, NOT evidence of defects or completed features in Workbench3D. Both open and closed peer issues inform requirements. User research and paying customers are goals, not development stop-gates.

## No code reuse / provenance policy

- Requirements may be derived from observable behavior and written issue descriptions. All Workbench3D algorithms, UI, fixtures and tests must be original; do not copy third-party source code, textures, documentation, screenshots, sample model files, proprietary data or assets.
- Inspect any new dependency or test-file license and attribution before use. Preserve Workbench3D's MIT licensing and avoid GPL code integration. Use synthetic or explicitly licensed fixtures.
- Keep this register linked from SPRINTS.md and BACKLOG.md. A peer issue being closed never implies our task is Done. Workbench3D tasks are Done only after changes merge and CI/evidence is recorded.
- Tackle failures immediately and continue ready sprint work without waiting for customer evidence, routine approvals or speculative market validation. No invented demos, revenue, tests, or deployment results.
